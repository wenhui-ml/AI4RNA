## 一、撤回:我昨天的头条是一个恒等式

C1 用 RibonanzaNet 交叉配对 F1 从池中**挑**最大,又用同一个量**评**。`max ≥ median` 是算术,不是证据。

```
把同一个 Wilcoxon 喂 51 个任意正数 + 6 个零   ->  p = 2.65e-10   (报告值 2.638e-10)
把它喂 51 个 1e-9 的无意义增益               ->  p = 4.8e-13
```

拆开(47 个已交付靶标):

| | 中位 | 更好 | p |
|---|---|---|---|
| 出厂选择器 − 池中位(**真正的问题**) | +0.032 | 27/47 | 0.137 |
| 池最大 − 池中位(**构造上必为正**) | +0.211 | 47/47 | 1.2e-09 |
| 池最大 − 出厂(**昨天的头条**) | +0.184 | 41/47 | — |

**换独立裁判。** 在同时有 RNet 分和试管测量的真实设计上,按 RNet 取 argmax 值多少:

| 池类型 | F1=1.000 占比 | 顶端并列 | argmax 的**湿实验**增益 |
|---|---|---|---|
| Eterna(饱和) | 77.4% | 78 条 | **−0.30**(21/56, p=0.79) |
| M2(不饱和) | 0.0% | 2 条 | **+0.55**(21/35, p=0.022) |
| **我们的池** | **3.9%** | **10 条** | → M2 区间 |

预注册门槛 ≥1.0 分 → **KILL**。同时撤回口头引用的 **+1.74 分**:无落盘证据(已复核,唯一的 1.74 是 07-30 的成本系数)。

## 二、"尺子偏心"这个借口也不成立

RNet 训练见过 Eterna 和天然序列,没见过我们的 —— 但检验 **KILL**,且符号相反。方法表说明了原因,按"离天然序列多远"对齐后:

```
我们                28.5% 同一性   RNet 0.816
Struct2SeQ          28.9%          0.984      同新颖度的学习型设计器
3DRNA               29.0%          0.000
gRNAde-no3d         30.7%          0.938
MPNN-RFdiff         32.0%          0.954
codesign-RFdiff     32.6%          0.935
```

**我们是一个物理设计器:赢下所有物理设计器,输给所有学习型设计器。**

生成缺口第一次量到分布层面:我们池中位对同新颖度同行 **−0.209,0/57**,p=5.3e-11;池里强于同行典型设计的候选只占 **7.5%**(持平应为 50%),**10 个靶标整池没有一条**达到同行中位。修掉抓取污染后缺口收窄到约 −0.12 —— **整条分布被压低,不是"只是没挑好"。**

## 三、本期唯一的正面结果:出厂证书第一次接受外部检验

4,560 条**真正被合成过**的设计,用出厂面板逐条裁决,对照湿实验:

```
未控制方法   +4.75 分   43/51 靶标   p = 4.9e-08
控制方法后   +1.90 分   41/58 格子   p = 1.2e-04   <- 请用这个
```

**我自己的复核砍掉了六成。** 面板对各方法的确认率从 3DRNA 的 **0.0%** 到 Struct2SeQ 的 **70.6%**,而这些臂之间湿实验本身就差 29 分 —— 所以"确认组更好"里有一部分只是"Eterna 比 3DRNA 好"。在**同靶标 × 同方法**格子内重算才是干净的。

> 局限:合格格子 58 个,主要由 Eterna 和 M2 两个大臂支撑,所以 +1.90 主要是在这两个臂内测到的。

**判据作为排序器更弱,作为闸门很强。** 这两件事我们一直混着用:

```
靶标内 Spearman(判据, 湿实验)   RNet +0.421   面板 +0.263   差 +0.134, 45/57, p=3.4e-05
控制方法后                       RNet +0.229   面板 +0.122   差 +0.088, 50/79, p=0.0155
两个判据彼此一致度                            +0.395        —— 量的不是同一件事
```

作为尺度:**被撤回的重排增益 +0.55 分;我们本来就在发的这道闸门 +1.90 分。**

## 四、一条真实的产品缺陷,和它没那么大的价值

`_run` 扫描 DesiRNA 写的每个文件取前 200 条 —— 包括 `trajectory_files/`,即**求解器自己已经淘汰的中间态**。300s 档三个轨迹文件各 1,450 条,对 20 条真答案。**这些中间态被当候选发出、被证书认证、交到用户手里。**

修前先量(同一次运行两臂):上报答案比轨迹态高 **+0.107**,46/57,p=2.8e-06。

**受控 A/B(两臂求解轨迹逐字节相同,只差一个环境变量):**

```
覆盖    新 33/57   旧 34/57      只丢 P16,没有新增
质量    配对差 +0.000            更好 2,更差 5,持平 50/57,p = 0.554
变动    57 个靶标里只有 7 个交付序列变化;净和 −1.036,均值 −0.018
```

**这是一次纯正确性修复。** 之前那个"47→43、代价 4 个靶标"**是噪声**。

> 读数陷阱(已写进输出):边际中位 0.483 vs 0.621 看着像差距,不是 —— 两臂各 25 个靶标计 0.0,中位数压在交付/未交付分界上。配对检验才有意义。

## 五、求解器从来就不可复现,今天修好了

追查经过三个假设,**前两个是我的,都错**:

1. ~~seed 是装饰品~~ —— 错。但发现 **`-seed 0` 是 DesiRNA 的「请随机」哨兵值,而 0 是我们全项目默认值**:每个 benchmark、每次阶梯、每个"三个 seed 的对比",都在请求随机化。
2. ~~墙钟主循环~~ —— 也错。设了步数上限后仍 Jaccard 0.003。
3. **`PYTHONHASHSEED`** —— DesiRNA 遍历字符串键的 dict/set,Python 默认每进程随机化哈希,迭代顺序变→尝试的突变变。

```
PYTHONHASHSEED=0 + 墙钟 -t 20,无步数上限   三次完全相同,Jaccard 1.000
步数上限 -s 40,哈希种子放任              Jaccard 0.000
```

**修复是一个环境变量,产品的秒预算完全不动。** 同一个问题问两次现在能拿到同一份证书 —— 这直接补 ⑤。

**不夸大:** 墙钟下步数仍随负载漂移,是**改善不是保证**(三个靶标里答案两个复现、池无一完全复现);加上步数预算才彻底闭合(三靶标全部返回逐字节相同的 200 条池)。所以 `-s` 也接上了,只给需要受控对比的实验用。

**追溯影响:** 8-06 的 `agent_ladder_lottery` 曾发现长档的解"像彩票",归因为**不同 seed 之间**的差异 —— 实际上**同一 seed 重跑也会给出第四个答案**,那三个 seed 从来不是三个受控条件。结论(彩票)不受影响甚至更强,但"seed 是受控变量"这个前提一直不成立。

## 八、诚实的限制

1. **+1.90 主要在 Eterna/M2 两个臂内测到**,外推到我们自己的设计没有直接证据 —— 我们的设计没有、也不可能有湿实验对照。
2. **生成缺口的量级是上界**:拿他们**已挑选提交**的设计比我们**未挑选的原始池**。
3. **墙钟下不保证复现**;要严格复现需步数预算,而产品卖的是秒。
4. **本期没有做出新能力。** 它把一批"以为成立"的东西变成了"测过",并让后续任何改动第一次有了可复现的基线。
