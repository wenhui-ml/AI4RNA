## 一、唯一的正面能力结果:出厂证书第一次接受外部检验

4,560 条**真正被合成过**的设计,用出厂面板逐条裁决,对照他们的湿实验测量:

```
未控制方法   +4.75 分   43/51 靶标   p = 4.9e-08
控制方法后   +1.90 分   41/58 格子   p = 1.2e-04   <- 请用这个
```

**我自己的复核砍掉了六成。** 面板对各方法的确认率从 3DRNA 的 **0.0%** 到 Struct2SeQ 的 **70.6%**,而这些臂之间湿实验本身就差 29 分 —— 所以"确认组更好"里有一部分只是"Eterna 比 3DRNA 好"。必须在**同靶标 × 同方法**格子内比。

**但它作为排序器很弱,作为闸门很强 —— 我们一直混着用:**

```
靶标内 Spearman(判据, 湿实验)     RNet +0.421   面板 +0.263    差 +0.134, 45/57, p=3.4e-05
```

> 顺带修正:8-07 报的 +0.155 是对**离散等级**测的,今天用**连续召回**重测得 +0.263。同一面板、更细的读数 —— **证书在把连续召回四舍五入成等级时,丢掉了自己大部分的预测信号。**

## 二、覆盖 43/57 → 57/57:判据的工作点从来没对着现实标定过

出厂工作点是"至少一家神谕把交叉茎**全部**复现"(τ=1.0),它是**在硅内**标定的(0.4% 假阳率 on 随机序列)。那 14 个 not_found 正是被这个未经现实标定的阈值挡住的。

**前沿不是单调的,最好的点在松的那一端:**

```
平均交叉召回阈值        通过率     试管分离度    格子数
  >= 0.05             84.5%        +3.98       44
  >= 0.15             83.6%        +3.69       49
  >= 0.30             74.8%        +1.97       62
  出厂 k>=1 (τ=1.0)   57.8%        +1.90       58
  >= 0.70             20.8%        −0.07       51     <- 收紧过头,完全失效并反转
  >= 0.90             11.1%        −0.26       33
```

我是从网格里挑的最优点 —— **这正是今早毙掉 +0.250 的同一类错误**,所以先做了留出检验:在一半靶标上选阈值,到**没参与选择**的另一半上测,200 次随机划分。

```
留出半边分离度   选出的点 +3.37 分   对   出厂点 +1.93 分   更好 144/200 次
通过率           57.8%  ->  83.0%
```

**逼出的重构:**

> **"神谕完全看不见这个假结"是一个强而可靠的信号;
> "某一家神谕把它全看对了"是一个噪声很大的信号。我们发的恰好是噪声大的那一半。**

### 迁移检验 —— 覆盖数字值钱的唯一原因

全部标定自**别人合成的分子**;我们的设计是从头设计,永远不会有湿实验对照。所以必须问:**这道筛在我们自己的池子里分得开吗**(RibonanzaNet 当裁判,它从不进设计环,也不可能被这道筛拟合过)。

```
配对差中位 +0.174,过筛更好 7/11,p = 0.0104   通过
```

### 结果与归因

```
交付                43/57  ->  57/57
被救回的 14 个       交付 F1 中位 0.823(早退规则),13 个 ≥0.5,没有一个是 0
全部 57 个靶标       交付中位 0.800
L1 对全体真实设计    −0.242  ->  −0.075(仍为负,仍不通过)
```

**归因必须拆开,否则这个数是偷来的:**

```
3/14  (P06, P11, W13)   旧判据在新池上也能过  ->  搜索抖动,不是工作点的功劳
                                                (也说明基线把这 3 个判成 not_found 本身就是抖动)
11/14                   只有新筛能救           ->  工作点改动的真实贡献
```

我是因为看到 P06/P11 的平均召回到了 **1.000**(严格闸门本来就会放行)才去查的。

### 已落进产品:第三档 `knot_screened`

```
certified        三家神谕全票            (最强)
knot_confirmed   至少一家把交叉茎全对
knot_screened    平均交叉召回 >= 0.1     (新;最弱)
not_found        什么都没有
```

- **刻意不算确认**:代码里每个内部消费者都是 `verdict in ("certified","knot_confirmed")`,所以 agent 修复循环照常继续、CLI 仍非零退出
- 理由字段以 **"NOT CONFIRMED"** 开头,明说这是最弱一档,**"当作待验证的线索,不是已验证的设计"**
- **是白送的**:主循环为给 `knot_confirmed` 评级本来就把整池裁决了,新筛复用同一批折叠。冒烟:P01 180 秒 / W03 284 秒 —— **和它们过去"什么都不返回"时花的时间一样**
- **取第一个过筛的,不排序** —— 这是测出来的:整池排序**没有更好**(配对 +0.000,5/14,p=0.277),点估计还更差(0.823 vs 0.734),而 240nt 整池排序要 3.2 小时

## 三、生成缺口:不是分布被压低,是三分之一的候选完全没形成假结

按"离天然序列多远"对齐后,我们和同新颖度的同行比:

```
我们                28.5% 同一性   RNet 0.816
Struct2SeQ          28.9%          0.984      同新颖度的学习型设计器
gRNAde-no3d         30.7%          0.938
MPNN-RFdiff         32.0%          0.954
codesign-RFdiff     32.6%          0.935
Rosetta             36.0%          0.300      我们打赢的三家
3DRNA               29.0%          0.000
Rosetta-LoRes       43.0%          0.571
```

**我们是一个物理设计器:赢下所有物理设计器,输给所有学习型设计器。** "尺子偏心"这个借口被检验 **KILL**,符号还是反的。

**缺口在最简单的题上最大(同行三个区间都是平的,所以不是天花板压缩):**

```
交叉配对数      同行中位   我们中位     缺口
最少 1/3         0.941     0.538     -0.403
中间             0.974     0.789     -0.186
最多 1/3         0.953     0.861     -0.092
```

**而且形状是双峰,不是平移:**

```
最少交叉的 19 个靶标   候选 6960 条:F1 = 0 占 33.4%,F1 ≥ 0.9 占 17.5%
最多交叉的 19 个靶标   候选 3367 条:F1 = 0 占  7.0%,F1 ≥ 0.9 占 33.4%
```

6 个靶标的**池中位恰好是 0.000** —— 典型候选一个交叉配对都没复现;而同一池的最好能到 0.88–1.000。

**机制假设(尚未验证,上一轮的检验因解析 bug 作废,重跑被核数上限叫停):** 小假结对能量目标贡献小,求解器可以在满足自己目标的同时把它整个忽略;大假结绕不过去。`-nd on`(负设计,惩罚竞争构象)在小假结端有效、在大假结端无效 —— 与"竞争构象"一致,但那一轮的结论已随解析 bug 一并撤回,需重测。

## 四、求解器从来就不可复现,已修

追查经过三个假设,**前两个是我的,都错**:

1. ~~seed 是装饰品~~ —— 错。但查出 **`-seed 0` 是 DesiRNA 的「请随机」哨兵值,而 0 是我们全项目默认值**:每个 benchmark、每次阶梯、每个"三个 seed 的对比",都在请求随机化
2. ~~墙钟主循环~~ —— 也错。设了步数上限后仍 Jaccard 0.003
3. **`PYTHONHASHSEED`** —— DesiRNA 遍历字符串键的 dict/set,Python 默认每进程随机化哈希,迭代顺序变 → 尝试的突变变

```
PYTHONHASHSEED=0 + 墙钟 -t 20,无步数上限   三次完全相同,Jaccard 1.000
步数上限 -s 40,哈希种子放任              Jaccard 0.000
```

**修复是一个环境变量,产品的秒预算完全不动。** 同一个问题问两次现在能拿到同一份证书 —— 直接补 ⑤。

**不夸大:** 墙钟下步数仍随负载漂移,是**改善不是保证**(三靶标里答案两个复现、池无一完全复现);加上步数预算才彻底闭合(三靶标全部返回逐字节相同的 200 条池)。所以 `-s` 也接上了,只给需要受控对比的实验用。

**追溯影响:** 8-06 的 `agent_ladder_lottery` 曾发现长档的解"像彩票",归因为**不同 seed 之间**的差异 —— 实际上**同一 seed 重跑也会给出第四个答案**。结论(彩票)不受影响甚至更强,但"seed 是受控变量"这个前提一直不成立。

## 八、诚实的限制

1. **+1.90 主要在 Eterna/M2 两个臂内测到**(58 个格子),外推到我们自己的设计**没有直接证据** —— 我们的设计没有、也不可能有湿实验对照。
2. **新筛在它救回的 11 个靶标里,有 4 个根本分不开质量**(P01/P06/Q04 两边都是 0.000,P16 是 0.533 vs 0.536)。中位是被 W13/W03/P11/W04 撑起来的。
3. **生成缺口的量级是上界**:拿他们**已挑选提交**的设计比我们**未挑选的原始池**。
4. **墙钟下不保证复现**;严格复现需步数预算,而产品卖的是秒。
5. **L1 仍为负、仍不通过** —— 我们没有超过同行。变的是每道题都给答案,且答案是真的。
6. **交付的 0.823 仍远低于池中最好的 ~0.95** —— "面板决定『答不答』远比决定『答哪个』准",本周第三次独立出现。
