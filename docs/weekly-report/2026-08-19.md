## 二、覆盖 43/57 → 57/57:判据的工作点从来没对着现实标定过

出厂工作点是"至少一家神谕把交叉茎**全部**复现"(τ=1.0),它是**在硅内**标定的(0.4% 假阳率 on 随机序列)。那 14 个 not_found 正是被这个未经现实标定的阈值挡住的。

**前沿不是单调的,最好的点在松的那一端:**

```
平均交叉召回阈值        通过率     试管分离度    格子数
  >= 0.05             84.5%        +3.98       44
  >= 0.15             83.6%        +3.69       49
  >= 0.30             74.8%        +1.97       62
  出厂 k>=1 (τ=1.0)   57.8%        +1.90       58
  >= 0.70             20.8%        −0.07       51     <- 收紧过头,完全失效并反转
  >= 0.90             11.1%        −0.26       33
```

我是从网格里挑的最优点 —— **这正是今早毙掉 +0.250 的同一类错误**,所以先做了留出检验:在一半靶标上选阈值,到**没参与选择**的另一半上测,200 次随机划分。

```
留出半边分离度   选出的点 +3.37 分   对   出厂点 +1.93 分   更好 144/200 次
通过率           57.8%  ->  83.0%
```

**逼出的重构:**

> **"神谕完全看不见这个假结"是一个强而可靠的信号;
> "某一家神谕把它全看对了"是一个噪声很大的信号。我们发的恰好是噪声大的那一半。**

### 迁移检验 —— 覆盖数字值钱的唯一原因

全部标定自**别人合成的分子**;我们的设计是从头设计,永远不会有湿实验对照。所以必须问:**这道筛在我们自己的池子里分得开吗**(RibonanzaNet 当裁判,它从不进设计环,也不可能被这道筛拟合过)。

```
配对差中位 +0.174,过筛更好 7/11,p = 0.0104   通过
```

## 三之四、④ 的第三个造判据领域:**验证器仲裁**(8-18/8-19 新增,过了预注册确认)

**A6 通过为什么不由我解释:** 切点(秩差 0.23134)、估计量(每格一票)、成功条件、连**被检验的对照数值**都在新面板折叠之前提交并推送。而且**尺度免疫检查也是在结果不可能已知时跑的**:把旧样本按格内设计条数分档,落在冻结切点以上的比例是 27.5% / 29.3% / 22.7% / 21.9% / 25.0%(极差 7.4%),所以"新样本格子更大"这条借口**提前不可用**。

### 判据的形状,以及一个反向的真结果

> **学习型在格内相对自信落在顶四分位时跟它走(56–62%);反向不携带信息(抛硬币)。**

这也解释了 A4 那条对称规则为什么赢不了:在面板更自信的那一半上,跟学习型只有 51.3%,把决定翻过去等于在 50/50 区域里把仅有的优势换成零。

**A8 虽然无数据,却掉出一件和我当天倾向相反的事:**

```
RNet 把野生型排在全部 7 条随机之上:160/250 = 64.0%
面板 把野生型排在全部 7 条随机之上:217/250 = 86.8%   ← 面板赢
RNet 在 81/250 个格里对全部 8 条(含野生型)都给 0
```

**在这个人群上热力学面板明显是更好的尺子。** 两把尺子的优劣**依赖人群** —— 这正是"判据缺失"的内容,也是判据必须单侧条件化、不能简化成"信 RNet"的理由。A8 的无数据本身也是个结构性发现:**仲裁型判据可能没有"绝对灵敏度"这个量** —— 它不对单个设计发火,只存在于分歧上,而真值 vs 噪声是道容易题,两把尺子都做对(相悖率 1.49%)。

2. **新分子,但同一批 57 靶标。** 世上没有第二批带这个规模试管测量的假结靶标,这条移不掉。

### 三之四之二、A9:绝对灵敏度测了两次没拿到,但查出一条适用范围限制

A8 之后又跑了 A9,**跑之前把它的混杂也声明了**:难零假设人群是每格 1 条野生型 + 7 条**嵌套诱饵**(对去掉假结的骨架做 `inverse_fold`,再拿完整靶标判;严格档历史上对 183 条这类诱饵接受 0 条)。249/250 格成格,1976 条序列,只有 1 个靶标整格丢弃 —— 难例基本没缺。

**声明里先认的混杂:** 诱饵由 ViennaRNA 构造,而 pKiss/ShapeKnots 与它共用 Turner 参数族、RNet 没有这层关系,所以**绝对水平天生偏向面板**。因此主检验改成**对比**(顶档 − 底档,区间排除 0;均匀的面板优势造不出对比),"顶档越过 0.5" 降为更保守的次检验,并写死:**失败不可归因**,只记"测过、未拿到",不算判据被反驳。

```
出厂列,可用格 89,相悖的(野生型, 嵌套诱饵)配对 186
  底档 n= 24 单位16   跟学习型 6.2% [0.0, 18.8]  ✓ 下越 0.5
  中档 n=142 单位78   跟学习型 3.8% [0.0,  9.0]  ✓ 下越 0.5
  顶档 n= 20 单位18   跟学习型 5.6% [0.0, 16.7]  ✓ 下越 0.5
  【主检验】对比 顶−底 = −0.7%  聚类 CI [−16.7, +15.5]  跨过 0     → 不成立
第二人群(同长度其他靶标的天然序列,无共享误差路径):相悖配对 55 / 76 < 100 → 按声明记无数据
```

**按声明这次失败不可归因,但我不打算躲在那句话后面。** 5.6% 不是"轻微偏向面板",是彻底反转:**在(野生型, 嵌套诱饵)这类相悖上,两家判官分歧时几乎总是 RNet 错。** 而顶档——判据说该信学习型的地方——只有 5.6%。

**所以这一跑真正的产出是一条适用范围限制,而不是一个空结果:**

> **判据只适用于【同一靶标的两个可信设计之间】选一个,不适用于【真值 vs 诱饵】的鉴别。**

这和 ④ 的第一把尺子那一行是同一个道理(「判据适用于全部假结拓扑」:H-type 不成立,已限制适用范围,记 ❌)。**限制适用范围就是正确答案,但它必须进分母。**

它也和 A8 那个反向结果对上了:RNet 在天然假结上常常什么都看不见(81/250 个格里对含野生型的全部 8 条都给 0),而面板在这类人群上明显更好(86.8% vs 64.0%)。**两把尺子的优劣依赖人群** —— 这条本周出现了三次,而且是判据必须单侧条件化的根据。

**功效也要说清:** 顶档只有 20 个配对 / 18 个单位,对比检验的区间宽到 ±16%。声明的门槛是"总相悖配对 ≥ 100"(186 过了),但**没有对分档后的样本量设门槛**,这是我这次声明写漏的一处,记在案。

## 三之五、这两天撤回的不是数据,是**估计量的权重**

同一个错误类别在本项目里出现了**四次**,8-19 一天占两次:

| 出现 | 错误的权重 | 修正前 → 后 |
|---|---|---|
| 方法构成混淆(8-17 前) | 各方法的样本量 | +4.75 → +1.90 分 |
| `filter_stack` 汇总(8-18) | 跨格汇总 | 7.6 → 2.9 分 |
| 仲裁 A1(8-19) | 配对数(格大小) | 57.6% → 53.8% |
| 单侧判据 A5b(8-19) | 1/σ_cell(格内方差) | 75.1% → 64% |

**通用形式:证据单位是嵌套的时候,任何不显式固定权重的估计量,量到的是嵌套的几何而不是证据。**

**"按格聚类"只修了「依赖」,没修「加权」——这是两次不同的修正,我此前只做了第一次。**

**已经查过的账(这条教训的适用范围):**

```
+1.90(唯一的湿实验背书)  格内中位差 → 格中位,Wilcoxon 按格   → 不受影响,本来就是每格一票
ruler_gradient G5          格内差 → 跨格 Wilcoxon              → 不受影响
仲裁 A1                    配对加权                            → 中招,已撤回
仲裁 A5b                   1/σ_cell 加权                       → 中招,已改正
```

**旗舰的 +1.90 干净。** 中招的只有仲裁那两处,而且两处都在同一天被同一次审计抓到。

**审计的一个时序细节值得记:** `arbitration_audit.py` 的第一件事是 **C0 复现已发表的 A1**(57.6% / 7,858 配对 / 184 格,一致),复现不上就不许读下面任何一行。这一条把"我改了估计量所以数变了"和"我改了数据所以数变了"分开。

## 四、求解器从来就不可复现,已修

追查经过三个假设,**前两个是我的,都错**:

1. ~~seed 是装饰品~~ —— 错。但查出 **`-seed 0` 是 DesiRNA 的「请随机」哨兵值,而 0 是我们全项目默认值**:每个 benchmark、每次阶梯、每个"三个 seed 的对比",都在请求随机化
2. ~~墙钟主循环~~ —— 也错。设了步数上限后仍 Jaccard 0.003
3. **`PYTHONHASHSEED`** —— DesiRNA 遍历字符串键的 dict/set,Python 默认每进程随机化哈希,迭代顺序变 → 尝试的突变变

```
PYTHONHASHSEED=0 + 墙钟 -t 20,无步数上限   三次完全相同,Jaccard 1.000
步数上限 -s 40,哈希种子放任              Jaccard 0.000
```

**修复是一个环境变量,产品的秒预算完全不动。** 同一个问题问两次现在能拿到同一份证书 —— 直接补 ⑤。

**不夸大:** 墙钟下步数仍随负载漂移,是**改善不是保证**(三靶标里答案两个复现、池无一完全复现);加上步数预算才彻底闭合(三靶标全部返回逐字节相同的 200 条池)。所以 `-s` 也接上了,只给需要受控对比的实验用。

**追溯影响:** 8-06 的 `agent_ladder_lottery` 曾发现长档的解"像彩票",归因为**不同 seed 之间**的差异 —— 实际上**同一 seed 重跑也会给出第四个答案**。结论(彩票)不受影响甚至更强,但"seed 是受控变量"这个前提一直不成立。

## 五之二、⑤ 的新一格:证书第一次说出**自己能被骗的频率**(8-19,已进产品)

`knot_screened` 是最弱的一档,自它上线以来只报**分离度** —— 清了这一档的设计在试管里比没清的高 +3.37 分。它从来没报过一件用户更该知道的事:**这一档有多容易被骗**。严格档从建成起就有这个数(84.0% / 0.4%),弱档没有。

              灵敏度(250 条野生型)          随机序列假收(250 条)

**还标注了一件容易误读的事:** 严格档的**头条**灵敏度是 78.5%(93 条野生型上的**留出**值),这里的 84.0% 是同总体的**同集**值,两者差在分母而不在协议质量。弱档的 90.4% 是同集值,**不可与 78.5% 直接比**,字段里明写了哪个比较合法 —— 免得用户在两张证书上读到同一档的两个灵敏度。

**这一格记 ✅(用户可见、对着真值测的),那个 0.000 记 ❌(产品里确实存在、确实不成立)。** ⑤ 因此 9/12 → 10/14。

## 八、诚实的限制

1. **+1.90 主要在 Eterna/M2 两个臂内测到**(58 个格子),外推到我们自己的设计**没有直接证据** —— 我们的设计没有、也不可能有湿实验对照。
2. **新筛在它救回的 11 个靶标里,有 4 个根本分不开质量**(P01/P06/Q04 两边都是 0.000,P16 是 0.533 vs 0.536)。中位是被 W13/W03/P11/W04 撑起来的。
3. **生成缺口的量级是上界**:拿他们**已挑选提交**的设计比我们**未挑选的原始池**。
4. **墙钟下不保证复现**;严格复现需步数预算,而产品卖的是秒。
5. **L1 仍为负、仍不通过** —— 我们没有超过同行。变的是每道题都给答案,且答案是真的。
6. **交付的 0.826 仍远低于池中最好的 ~0.95** —— "面板决定『答不答』远比决定『答哪个』准",本周第四次独立出现,8-17 拿到了它最极端的实例:P14 的池中位 0.889,我们交 0.000。
7. **出厂阶梯是墙钟限时的,运行间本底噪声约 3.5%**(两次全量运行:36 个共同确认靶标里 1 个换了序列、1 个掉档)。所有小效应必须带这个底噪读。
8. **9 个 H-type 靶标被拓扑闸门挡在 `knot_confirmed` 之外**,交付走筛通道的第一条 —— 仅 P06/P11 两个靶标上就有 209 条已被面板完全确认的候选按设计被跳过。拒发标签是诚实的,把这 209 条的信息一起扔掉是浪费,尚未量化。
9. **选择器的收益全部由 RibonanzaNet 裁定,不是湿实验。** 唯一的湿实验背书(+1.90)关于**判据**,不关于**选择器** —— 换了选择器之后那条性质还成不成立,**没测**,这是下一步第一件事。
10. **换选择规则不是纯改进。** P17 从 0.909 掉到 0.000,8 个靶标变差;它修好 3 个零交付,也可能造出新的。
11. **`screen_first` 依赖"池的顺序 = 求解器自己的排序"。** 这是 DesiRNA 的实现细节,换求解器就不成立,**产品不该把它当成通用规律,而应显式地去要求解器的排序**。
12. **上线前必须修标签一致性**(§三之三末)。
