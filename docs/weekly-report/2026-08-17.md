出厂工作点是"至少一家神谕把交叉茎**全部**复现"(τ=1.0),它是**在硅内**标定的(0.4% 假阳率 on 随机序列)。那 14 个 not_found 正是被这个未经现实标定的阈值挡住的。

## 三、生成缺口:不是分布被压低,是三分之一的候选完全没形成假结

按"离天然序列多远"对齐后,我们和同新颖度的同行比:

```

Struct2SeQ          28.9%          0.984      同新颖度的学习型设计器

**我们是一个物理设计器:赢下所有物理设计器,输给所有学习型设计器。** "尺子偏心"这个借口被检验 **KILL**,符号还是反的。

**缺口在最简单的题上最大(同行三个区间都是平的,所以不是天花板压缩):**

**而且形状是双峰,不是平移:**

```

**机制假设(尚未验证,上一轮的检验因解析 bug 作废,重跑被核数上限叫停):** 小假结对能量目标贡献小,求解器可以在满足自己目标的同时把它整个忽略;大假结绕不过去。`-nd on`(负设计,惩罚竞争构象)在小假结端有效、在大假结端无效 —— 与"竞争构象"一致,但那一轮的结论已随解析 bug 一并撤回,需重测。

**验证结果(本节新增,8-17):机制成立,但只到池层面为止。**

DesiRNA 的目标函数解析有 bug(`parse_scoring_functions` 的 `return` 缩进错进循环,多项目标只有第一项生效),已打补丁并加了启动自检。补丁后重测:

```
交叉配对数        F1=0 占比降幅      来源
   8-18            −13.0%          用于挑臂的那组
  18-30            − 5.0%          留出集:19 个从未被任何一轮碰过的靶标
  30-88            − 3.5%          对照组
```

留出集的降幅在跑之前就被预注册**必须落在 −3.5% 与 −13.0% 之间**,否则按证伪上报。实测 **−5.0%,落在区间内,p = 0.0040**。不依赖补丁的单项臂 `mcc_only` 同向(−3.0%),但 **p = 0.02501,比 0.025 门槛高一丝 —— 方向性支持,本身不显著,按精确值报**。

**这是本项目第一个通过定量样本外检验的机制主张。**

### 5 个交付 0.000 的靶标:是选择缺陷,不是生成缺陷

```
靶标    出厂档位          池     交付     池内最好   池中位   >0.5 的条数
P02   knot_confirmed    200   0.000    1.000    0.545      104
P03   knot_confirmed    200   0.000    1.000    0.730      136
P09   knot_confirmed    201   0.000    0.889    0.000       30
P10   knot_screened     200   0.000    0.923    0.621      129
P14   knot_confirmed    200   0.000    1.000    0.889      176
```

**生成失败 0/5。** P14 那一池 176/200 条在 0.5 以上、中位 0.889,我们交了 0.000。**4 个挂着我们最强的 `knot_confirmed` 标签。**

损失定位到出厂规则的两步:

```
argmax |confirmed_by|   把 156 条已确认候选(F1 中位 0.634)压缩成 3 条(中位 0.552)
确定度打平器            再从这 3/4/2 条里挑走最差的一条 —— P02 (3/3)、P03 (4/4)、P14 (2/2)
                       随机全中末位的概率 1/24。P09 子集只有 1 条,无信息,不计入
```

打平器是**故意**偏好"折叠得不那么确定"的候选(我们的设计比天然假结确定约 3 倍)。它当初用 IPknot/Knotty/RNAPKplex 验证过。**但它和 RibonanzaNet 系统性反向 —— 这是"solved 是验证器的选择"打在我们自己产品上。**

### 这个诊断当时**证不了**的事,以及修法

那些池是用一个独立收池函数重收的。**出厂阶梯是墙钟限时的,一层返回多少候选取决于机器负载:**产品当时筛了 302–412,重收产生 312–451,**既不相等也不互相包含**。所以数据支持的是"同一个生成器可靠地造得出 1.000",**不是**"产品当时看见了却没给"。

修法:`certify.py` 加环境开关 `CERTIFY_POOL_DUMP`(不设完全不生效),在**产品自己进程内**记下每条被裁定候选的三氧化物召回、确认者、打平器读的确定度值。**行为不变性用三次运行验证(关/关/开)** —— 单独一对开/关分不清是开关的影响还是阶梯自身的抖动;实测两个靶标上只有 `generated_utc` 不同,开关侧没有任何额外差异。

**顺带第一次量出运行间本底噪声:** 两次独立全量运行,36 个都判 `knot_confirmed` 的靶标里 1 个交付了不同序列、1 个掉了档,**约 3.5%**。以后引用小效应必须带上这个底噪。

## 四、求解器从来就不可复现,已修

追查经过三个假设,**前两个是我的,都错**:

1. ~~seed 是装饰品~~ —— 错。但查出 **`-seed 0` 是 DesiRNA 的「请随机」哨兵值,而 0 是我们全项目默认值**:每个 benchmark、每次阶梯、每个"三个 seed 的对比",都在请求随机化
2. ~~墙钟主循环~~ —— 也错。设了步数上限后仍 Jaccard 0.003
3. **`PYTHONHASHSEED`** —— DesiRNA 遍历字符串键的 dict/set,Python 默认每进程随机化哈希,迭代顺序变 → 尝试的突变变

```
PYTHONHASHSEED=0 + 墙钟 -t 20,无步数上限   三次完全相同,Jaccard 1.000
步数上限 -s 40,哈希种子放任              Jaccard 0.000
```

**修复是一个环境变量,产品的秒预算完全不动。** 同一个问题问两次现在能拿到同一份证书 —— 直接补 ⑤。

**不夸大:** 墙钟下步数仍随负载漂移,是**改善不是保证**(三靶标里答案两个复现、池无一完全复现);加上步数预算才彻底闭合(三靶标全部返回逐字节相同的 200 条池)。所以 `-s` 也接上了,只给需要受控对比的实验用。

**追溯影响:** 8-06 的 `agent_ladder_lottery` 曾发现长档的解"像彩票",归因为**不同 seed 之间**的差异 —— 实际上**同一 seed 重跑也会给出第四个答案**。结论(彩票)不受影响甚至更强,但"seed 是受控变量"这个前提一直不成立。

## 八、诚实的限制

1. **+1.90 主要在 Eterna/M2 两个臂内测到**(58 个格子),外推到我们自己的设计**没有直接证据** —— 我们的设计没有、也不可能有湿实验对照。
2. **新筛在它救回的 11 个靶标里,有 4 个根本分不开质量**(P01/P06/Q04 两边都是 0.000,P16 是 0.533 vs 0.536)。中位是被 W13/W03/P11/W04 撑起来的。
3. **生成缺口的量级是上界**:拿他们**已挑选提交**的设计比我们**未挑选的原始池**。
4. **墙钟下不保证复现**;严格复现需步数预算,而产品卖的是秒。
5. **L1 仍为负、仍不通过** —— 我们没有超过同行。变的是每道题都给答案,且答案是真的。
6. **交付的 0.826 仍远低于池中最好的 ~0.95** —— "面板决定『答不答』远比决定『答哪个』准",本周第四次独立出现,8-17 拿到了它最极端的实例:P14 的池中位 0.889,我们交 0.000。
7. **出厂阶梯是墙钟限时的,运行间本底噪声约 3.5%**(两次全量运行:36 个共同确认靶标里 1 个换了序列、1 个掉档)。所有小效应必须带这个底噪读。
8. **9 个 H-type 靶标被拓扑闸门挡在 `knot_confirmed` 之外**,交付走筛通道的第一条 —— 仅 P06/P11 两个靶标上就有 209 条已被面板完全确认的候选按设计被跳过。拒发标签是诚实的,把这 209 条的信息一起扔掉是浪费,尚未量化。
9. **选择器的收益全部由 RibonanzaNet 裁定,不是湿实验。** 唯一的湿实验背书(+1.90)关于**判据**,不关于**选择器** —— 换了选择器之后那条性质还成不成立,**没测**,这是下一步第一件事。
10. **换选择规则不是纯改进。** P17 从 0.909 掉到 0.000,8 个靶标变差;它修好 3 个零交付,也可能造出新的。
11. **`screen_first` 依赖"池的顺序 = 求解器自己的排序"。** 这是 DesiRNA 的实现细节,换求解器就不成立,**产品不该把它当成通用规律,而应显式地去要求解器的排序**。
12. **上线前必须修标签一致性**(§三之三末)。
