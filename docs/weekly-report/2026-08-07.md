## 这一天最重要的一件事:证据第一次从「没被驳倒」变成「被证实」

### 先说清楚这两件事的区别

我们此前所有的证书,严格讲都是**非驳倒**:

> 三个热力学预测器拿到这条序列,**没有反对**靶标那些交叉配对。

哪怕对上湿实验的 SHAPE 数据也还是非驳倒 —— **SHAPE 只能说"这个核苷酸被约束住了",说不出"它跟谁牵着手"**。低反应性可能来自意图中的配对,也可能来自别的碱基、别的堆叠、镁离子。

**补偿突变(mutate-map-rescue)是另一种东西。** 对一个被主张的碱基对 (i, j):

```
把 i 突变掉                  -> 若配对是真的,j 的保护【应该消失】
再把 j 补偿性地突变回互补     -> 若配对是真的,保护【应该回来】

rescue_factor = 双突变恢复了多少 SHAPE 扰动    0 = 没有证据  1 = 完全恢复
```

> **这不是"没人反对",这是"我们预言了一个反事实,然后它真的发生了"。**

### 结果

数据:Eterna OpenKnot 的 M2R 实验,**1,412 个交叉配对**(就是让靶标成为假结的那些配对),来自 20 个靶标 × 9 种设计方法的 160 条设计,每一对都被真做出来、真突变过、真上机器测过。

```
我们的三个神谕里,有几个确认了这个配对          真实分子怎么说
────────────────────────────────────────────────────────────────
0 个   n=267    补偿恢复中位 0.233    52.4% 的配对【根本不存在】
1 个   n=236                0.394    32.2%
2 个   n=456                0.470    19.3%
3 个   n=453                0.491    14.1%
```

**单调。而且是在真实分子里单调。**

| 预注册检验 | 结果 |
|---|---|
| **C0 阴性对照** 野生型序列根本配不上的 150 个碱基对,恢复应更低 | 0.196 对 0.452,**p = 1.8e-27**,通过 —— 测定确实能分辨真假 |
| **H1** 被至少一家确认的交叉对恢复更好(设计内比较) | 中位差 +0.061,**p = 0.0033**,通过 |
| **H2** 确认的家数越多越好 —— 即 k 阶梯是否携带信息 | 中位 rho +0.275,**p = 5.8e-05**,通过 |

> **H2 才是要害** —— 但**它的口径必须说准,我第一版说错了**(见下面的复核一节)。
> H2 测的是**每个碱基对**有几家确认,不是**证书的 k**(那是每条设计的量)。
> 前者极强(**三家确认的配对对无人确认的,无阈值检验 p = 2.1e-28**);
> 后者补测之后**成立但弱得多**:靶标内 rho +0.396,**p = 0.0147,只有 17 个簇,而且是事后跑的**。
> **正确的说法是:面板的【逐对】判断在分子里确实有序,这支持阶梯背后的机制;证书阶梯本身是"有支持",不是"已确立"。**

## 同一天,我们也发现自己一直在低报错误率 35 倍

```
出厂证书引用的误收率      0.4%     <- 对【随机序列】测的
对着现实的假阳性率       14.1%     95% [10.1%, 18.6%]
                                   面板三家一致确认、而分子拒绝形成的交叉配对
```

**这不是发现别人的错,是发现我们自己的零假设弱得没意义** —— 一条随机序列本来就没理由形成假结,通过它几乎不需要本事。

> **正确的读法从今天起是**:
> **"三家一致"意味着 —— 大约每 7 个这样的碱基对里,有 1 个在真实分子中并不存在。**

已写进产品(`certify.py` 的 `_INTERVENTION`),证书现在同时报两个数,并且**逐等级报**:

```
k=1  该等级的配对在真实分子中缺失 32.2%
k=2                              19.3%
k=3                              14.1%
```

**注意随机序列那个 0.4% 在三个等级上完全一样 —— 它对等级毫无分辨力。新的这个有。**

> ⚠️ **但 14.1% 这个数,几乎全是【阈值】做出来的,这一点我第一版没说,必须补上。**
> "配对不存在"要在 rescue 的哪里下刀,完全改变这个数:
>
> ```
> 下刀处      三家一致的缺失率      无人确认的
> < 0.00           2.4%              15.7%
> < 0.25          14.1%              52.4%
> < 0.50          51.7%              78.7%
> ```
>
> 而我给 0.25 的理由 —— "借用 OpenKnot 自己判'配对'的 0.25" —— 是一个**类别错误**:
> **OpenKnot 的 0.25 切的是归一化反应性,rescue_factor 是恢复的 RMSD 比例。数字碰巧一样,量根本不是一回事。**
>
> **真正站得住的是不依赖阈值的那句话:三家一致的配对,其 rescue 分布整体高于无人确认的,p = 2.1e-28。**
> 产品里现在阈值和数一起走,并附整条扫描曲线。

## 我对这个结果做的自我攻击(三条,全部挺住)

这个项目的规矩是:**结果出来之后,先由我自己当对手。** 这次找到三条:

### 异议 1:我在别处都加了 SN_filter,唯独这里忘了

信噪比未过滤的行占 5.0%。重算:

```
仅 SN_filter=1:  三家一致的假阳性 14.1% -> 13.8%
                 H2 中位 rho +0.275 -> +0.289,p = 8.3e-05
```
**方向不变,甚至更干净。**

### 异议 2:面板会不会只是在读「碱基对强度」,根本没在读结构

这条最危险。我们的神谕偏好热力学上强的配对;而强的配对被打断时 SHAPE 扰动更大、修复时恢复也更明显 —— **如果 H2 只是这个,那"阶梯携带信息"就是幻觉。**

```
碱基对强度本身与 rescue 的相关        rho = +0.083   (很弱)
未控制强度   中位 rho +0.226   p = 0.000207
控制强度后   中位 rho +0.240   p = 0.000771     <- 不降反升
```

**面板读的是结构,不是碱基组成。** 附带一个机制线索:**「0 家确认」那一档里,18% 的碱基对连设计自己的序列都配不上** —— 面板拒绝它们是对的。

### 异议 3:H3 的置信区间把同一分子里的配对当成了独立观测

453 个配对来自 60 条设计,一个分子里的配对共享它的折叠、归一化和实验批次。改用**按设计重抽样的簇自助法**:

```
原 Clopper-Pearson  [11.1%, 17.7%]     <- 假设独立,偏窄
簇自助法            [10.1%, 18.6%]     <- 产品引用这个
点估计 14.1% 不变
```

## 另一件事:失败第一次有了标价(② +1)

产品此前遇到解不出来的靶标,就返回 `not_found` 然后停住。而本周量到求解器按**墙钟**限时,同一请求重跑判决会翻转。那么**一次失败值不值得重抽一次?**

在**从未用过的种子**上前瞻重测(预注册 P1/P2/P3 全部通过):

```
重试 1 次    救回约 12%                成本 +1x
重试 3 次    救回约 24% [7%, 50%]      成本 +3x
全部救回都发生在最贵的 180s 档 —— 【没有便宜版本】
每救回一个靶标 $0.60
```

> **顺手抓到我自己脚本里的一个定价错误**:它原本把"三个种子买到的 24%"标在"一次重试"的价签上。
> **赔率和价格必须描述同一笔买卖。** 已修正。

这条改的不是求解能力,是**产品形态**:不懂 RNA 的用户拿到的不再是一个沉默的失败,而是**一个知道自己值多少钱的失败**。

## 同一天的第二个实验,给出了**方向相反**的答案 —— 这一段是本期最该读的

干预级实验回答的是"**我们的判据是不是真的**"。第二个实验回答的是另一个问题:
**"和领域里最好的做法比,我们值几斤几两?"**

数据:同一批 OpenKnot,**27,362 条去重设计**(剔除突变体与野生型),57 个靶标,11 个生成器,每条都有实测 SHAPE 分。而同一张表里还有一列 **`RNet_F1_crossed_pair`** —— **RibonanzaNet 的预测**,也就是"从湿实验数据里把判据学出来"那条路线的答案。**对手的答卷和我们的答卷,躺在同一张表上,对着同一个标准分。**

```
主分析总体 21,801 条(已标定拓扑),神谕失败 0

not_confirmed   n=9367   实测分中位 84.0   >80 占 63.2%
k=1             n=5302              86.8          74.8%
k=2             n=5655              90.1          84.9%
k=3             n=1471              90.1          82.9%
certified       n=   6              94.8         100.0%
```

| 预注册检验 | 结果 |
|---|---|
| **H1** 等级预测实测分(靶标内) | 中位 rho **+0.155**,33/42 正向,**p = 1.4e-05**,**通过** |
| **H2** 不只是在读生成器质量(同靶标同生成器内) | 中位 rho **+0.079**,**p = 3.3e-04**,**通过**(但效应很小) |
| **H3** 与 RNet 正面对比(双侧) | RNet **+0.364** 对我们 **+0.155**;差 **−0.169**,42 个靶标里我们只在 11 个上更好,**p = 2.6e-04** |
| **H4** 扣掉 RNet 后我们剩多少独立信号 | 中位 rho **+0.037**,p = 0.0304,**未过门槛 0.0125** |

### 这四行合起来说的是什么

> **H1 + H2:我们的等级确实预测真实世界,而且不是生成器质量的影子。这是真的。**
>
> **H3:我们输了,而且输得显著 —— 对手的相关性是我们的 2.3 倍。**
> 这一条**在跑之前就写明了"我们预期会输"**。RNet 就是在这类化学 mapping 数据上训出来的,热力学面板不该赢它。**H3 存在的唯一目的,是让 H4 不能靠回避对手来伪装成胜利。**
>
> **H4 才是判决:扣掉 RNet 之后,我们剩下的独立信号是 +0.037,过不了自己定的门槛。**
> **直白说:在【观察层面】,我们的热力学面板基本上是 RNet 的一个更差的影子。**

### 两个实验为什么不矛盾

```
干预级(M2R)     我们的判据【是真的】—— 它排序的东西在分子里确实按那个顺序存在
观察级(SHAPE)   我们的判据【不是最好的】—— 学出来的模型在同一件事上更准
```

**"是真的"和"有竞争力"是两件事,而我们这一天同时拿到了这两个答案的相反符号。**
这也是为什么 ④ 的分数会掉:**我们终于测了"我们到底强不强"这个一直没敢测的问题,答案是不够强。**

### 一个意外的次要结果

   中位 rho +0.335,10/10 全部正向,p = 0.00296

**在我们主动放弃使用主规则的那一族上,等级反而预测得更好。** 现在还不知道为什么 —— 记下来,不解释。

另外 **`certified`(面板对整个结构一致)整个总体里只有 6 条**(21,801 分之 6)。这一级实测分最高(中位 94.8,100% 超过 80),**但它稀有到几乎不构成一个可用的产品等级**。
