## 本周做了什么:四个例子

### 例一:180 秒那一档,烧掉四成算力,买不回任何东西(② +2)

用户要一条 RNA 序列,系统按预算逐档加时间:5 秒 → 15 秒 → 60 秒 → 180 秒。**没人量过最后一档值不值。**

量了之后:

```
只跑 5 秒       交付  79 个靶标      花 14% 的时间
跑到 60 秒      交付 102 个靶标      花 59% 的时间
跑满 180 秒     交付 105 个靶标      花 100% 的时间
```

**最后一档多花 41% 的算力,多交付 3 个靶标 —— 而这 3 个在统计上和零分不开。**

> ⚠️ **"和零分不开"要带检验力才诚实**:131 个靶标上,这个设计只能排除 **10% 以上**的真实损失(真实损失 2% 时只有 12% 把握测出,5% 时 47%)。**它排除的是"大损失",不是"没有损失"。**

改动:`standard` 预算从 `(5,15,60,180)` 变成 `(5,15,60)`。想多花的人仍可以要 `best_effort`,只是**不再默认收这笔钱**。

> **为什么这条能进产品,而本周另外两条改进被我自己否掉了**:这个 40.8% 是在**131 个从没用过的靶标**上重新验证的。第一次看到它是在另一批靶标上,而那个"最省的点"是**看完结果才挑出来的** —— 直接采用,就等于看完考卷再定及格线。所以换了一批靶标、事先写死门槛,重跑一遍。

### 例二:我们一直在扔掉已经赢到手的证据(④)

产品给假结发证书时,会问三个独立的预测器"这条序列对不对"。**三个都同意,比只有一个同意可信得多。**

但代码是这样写的:**找到第一个"至少一家同意"的候选,就用它,不再往下看**。而候选池早就生成好、也早就算过了。

```
250 个靶标                        改之前    改之后
  拿到"三家都同意"证书的靶标         8         80
  只拿到"一家同意"的靶标           135         10
```

**61.6% 的靶标本可以拿到更高等级的证书,而更好的那条序列就躺在同一个池子里。** 改动之后没有一个靶标变差,也没有多花一分钟算力(顺带发现三个预测器对同一条序列被重复调用了两遍,一并合并了)。

> **这个数字是【同一个候选池上跑两种策略】的精确回放,零混杂:250 个靶标,提升 154 个,下降 0 个。**
> 我最初引用的是"两次独立运行对比"的 17:0 —— 那个有混杂(求解器按墙钟限时,两次跑看到的池子不同),周末审核时换成了上面这个干净的。

### 例三:证书现在会说出自己有多少斤两(④)

老问题:我们发的证书,换一家裁判还成不成立?

本周请了**三个从未参与过我们任何规则的外部裁判**来判,而且刻意选了**三种完全不同的算法**(启发式拼接 / 精确动态规划 / 整数规划 + 学习模型)。它们互不冗余(一致度 kappa 只有 0.11–0.34)。

关键是**不能只看同意率** —— 这个领域**每个预测器连天然的真结构都认不全**:

```
三个裁判在【天然真结构】上的自身上限:  66.7%   73.7%   46.2%
```

对着这个上限重读我们的证书:

```
一家同意 (k=1)   只有上限的 0.10x ~ 0.62x
两家同意 (k=2)   0.22x ~ 0.65x        <- 和一家几乎没差别
三家同意 (k=3)   0.84x ~ 1.47x        <- 台阶在这里
```

**这是一个台阶,不是斜坡:面板知道的东西,绝大部分花在最后一票上。** 这些数字现在**直接写进证书**了(`KNOT_GRADES`),用户看到的不再只是"通过",而是"通过,以及这个等级在外部眼里值多少"。

> **底线仍然是"一家同意就发证"**,没有提高。因为提高到"三家同意"会让 **68% 的靶标什么都拿不到** —— 而 k=1 并没有被证明**错**,只是被证明**比天然结构更难被外部仪器认出**。对一个没有别的途径拿到答案的用户,收回答案是实打实的损失。

### 例四:同分的两条候选,该给用户哪一条(④)

上面例二解决了"别扔掉更高等级的候选"。但**等级一样**的时候呢?原来是"谁先出现给谁",纯属偶然。

本周量到一个此前没人看过的事实:

```
平均位点熵(越小 = 折叠越"确定")
  天然假结      0.2985
  我们的设计    0.0869      <- 比天然【确定】约三倍
```

**我们造出的序列,对自己的嵌套折叠比任何天然假结都更自信。** 而一个基于概率的假结预测器面对这种序列**无从下手** —— 嵌套结构把概率占满了,**没有份额留给让它成为假结的那些交叉配对**。

于是改成:**同等级时,优先给那条"没那么过度确定"的**。用**从未用过的种子**在 251 个靶标上前瞻检验:

```
外部裁判       IPknot        Knotty       RNAPKplex
接受率      21.8% -> 27.0%  62.1% -> 67.3%  52.8% -> 50.8%
            (29胜16负)      (42胜29负)      (不显著)
```

> **但纯按熵挑完全无效(34 胜 34 负)。** 熵是**并列打破器,不是选择器** —— 说"系综质量决定候选好坏"就是错的。
> 对照也起了作用:**按 GC 挑显著更差(14:32)**,这才排除了"其实只是碱基组成"的解释。
> 代价:只占三家预测器耗时的 **0.6%–1.0%**,而且只在真的出现并列时才算。
>
> ⚠️ **这一条是本周三个改动里最弱的,必须照实说**:p=0.0362,而这次运行一共做了 9 个方向检验,**Bonferroni 门槛是 0.0056 —— 它过不了族内校正**。P1 是跑前唯一指定的主检验、其余为描述性,所以它不是筛出来的;但**它的强度就到这里**。
> 另外,"我们的设计比天然确定三倍"这句话**已撤回,不作为发现**:设计是为靶标优化出来的、天然不是,优化过的序列折叠更确定近乎构造使然(组间差 0.212,组内差只有 0.026)。**并列打破器靠的是同靶标同等级候选之间那个小得多的差(+0.028),那一条由前瞻检验支撑,不受影响。**

## 本周否掉的(和做成的一样重要)

| 想做的事 | 为什么没做成 |
|---|---|
| 用"可设计性预测"提前判断哪些靶标不值得算,省钱 | **省不到**。一个**完美先知**最多也只能省 35.6%,因为那就是失败靶标消耗的全部时间;最贵的 10 个靶标里 **7 个是成功的** —— 贵的那批不是失败的那批 |
| 出厂规则改成"只发 ShapeKnots 确认的证书" | 换个裁判就不成立了。它的优势在第二个裁判上腰斩、第三个裁判上再腰斩 |
| 把预算砍到只剩 15 秒(更省) | 真的会丢证书(8 丢 / 1 得,显著)。**省 65% 但有代价 —— 不划算** |
| **给 agent 用的那条阶梯也砍掉 180 秒档** | **前瞻检验推翻了我自己的理由。** 在 286–400 nt 的长靶标上,砍掉之后 **0/10、0/10、1/10** —— 那是唯一能解长靶标的一档(**注:该实验的预注册阈值判定悬在少数几次抽样上,3 个靶标恰好落在 4/10 的刀刃;但"截断后 0/10"这一条与阈值无关**) |
| **纯按"系综确定度"挑候选** | **34 胜 34 负**,完全持平 |

**本期自我推翻 8 次,累计撤回 24 条,没有一条是被外部指出的。**

**其中两次,如果我信了自己【事后找的理由】,就会把产品改坏:**
- agent 阶梯那 6 个靶标看起来像"运气好中的彩票"(3 个种子里只中 1 个)→ **10 个种子上是 4/10,是真能力**
- 猜"我们的设计系综太散所以被拒" → **方向完全相反,是过度确定**

另两条撤的是**我自己同一个下午刚写下的结论**:
- 上午写"面板一致 = 更可信" → 下午拆开发现携带信息的是**其中一家**,不是"一致"
- 写"k=1 是靶标本身的性质,救不了" → 那个检验**根本看不见这么小的效应**,是没检验力,不是没效果

## 本周新量到的两个"以前不知道"的事实

**1. 同一个请求,问两次可能给出不同答案。**

```
cheap 预算(5 秒)   同配置重复,判决翻转 22.9%
standard 预算       翻转 5.8%
```

求解器按**墙钟**限时,同样的种子在机器忙闲不同的时候探索的候选数不同。**此前没有任何一个对比实验被拿这个校过** —— 几个点的差可能只是机器当时忙。现在所有配对实验都改用方向性检验。

**2. 加预算买到的是"能不能交付",不是"交付得更好"。**

```
预算从最低档提到满档,251 个靶标上等级提升 +0.749 级 (p=1.4e-11)
  其中 47 个是【从拿不到证书变成拿到证书】
      14 个是已有证书的等级变高
```

## 三堵绕不过去的墙(这才是需要外部灵感的地方)

**墙一:判据是"模型相对"的。** 我们的假结证书 97.1% 换一家裁判就可能不成立。三个算法完全不同的外部裁判两两 kappa 只有 0.11–0.34,而它们**认天然真结构也只有 46.2%–73.7%**。我们的应对是把这件事量化并写进证书,而不是假装有绝对判据。**有没有更强的做法?**

**墙二:第二把尺子的物理对应,被全世界的数据总量封顶在 ~70 nt。** 这类测量全球大约只有 **7 个分子系统**做过,RMDB 上的构建体我们 **27/27 全在手**。**有没有别的实验模态可以替代?**

**墙三:搜索能力从头到尾是 0。** 同预算三臂 62/61/60,七条轴 0 恢复。我们所有改进都在**判断**和**选择**上,**没有一条改进了"找到更好序列"的能力**。设计能力全部来自外部求解器。**这是最大的空白。**

> 本周新冒出的一条线索,可能是墙也可能是门:**我们的设计比天然结构"确定"约三倍。** 据此做的改动有效但很小(+5.2 点),纯按它挑则完全无效。
> **"设计出的序列过度确定"是不是一个更普遍的问题?有没有直接优化系综形状的设计方法?**
