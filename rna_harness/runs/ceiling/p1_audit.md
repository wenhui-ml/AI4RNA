## 一、撤回:"合池把格数从 110 提到 170"

**声明和执行器里都这么写,而它是错的。**

```
第四批格 110   第五批格 60   【交集 60】   并集 110
第五批 60/60 个格【本来就在第四批里】
```

**合池一个格都没加。** 它把 60 个格【变成两倍大】(24 -> 48),格数从 110 到 110。
可分开的单位:A15 是 64,P1 是 68 —— **多了 4 个,不是多了 60 个。**

**为什么**:第四批已经从每一个 >=24 条的格里抽走 24 条,所以"剩余还有 >=24 条"的格必然是
第四批也抽过的那些。要真的【新增格】,per_cell 必须小到能开出第四批开不了的格:

```
per_cell=24 -> 新格   0  合池 110      <- 我实际跑的
per_cell=20 -> 新格   7  合池 117
per_cell=16 -> 新格  23  合池 133
per_cell=12 -> 新格  44  合池 154
per_cell=10 -> 新格  60  合池 170      <- 声明里那个「170」只在这里成立
per_cell= 8 -> 新格 114  合池 224
```

**我把 110 和 60 直接相加得出 170,从没检查过两批的分组键有没有重叠。** 这和第 33 条同族:
我测了新样本自己的边缘计数(60 个格能供 24 条),**没测它与已有样本的【关系】**。→ **第 35 条。**

## 二、撤回:"区间窄了六倍,所以这是一次对零的测量而不是没测到"

`boot()` 自举的是**中位数**(`stat=st.median`)。而 B 的中央是一堆钉在零上的并列:

```
合池 B:可分开格 68,精确为 0 的 6 个(8.8%)
        排序后中央五个  [0.0, 0.0, 0.0, 0.0002, 0.0015]
        10/25/75/90 分位 [-0.1374, -0.0221, +0.0185, +0.0556]
        中位 +0.00000   均值 -0.02094
```

**区间窄是因为并列把中位数钉死了,不是因为离散度小** —— 10/90 分位跨 0.19,离散度并不小。
所以"六倍的区间 ⇒ 我们拿到了功效"这个推理**不成立**。

**而且跨判官比区间宽度本身就是松的**:A15 的质量量是 IPknot+RNAPKplex 的交叉召回,P1 的是
RibonanzaNet 的 f1c。同为 0–1,但**不是同一个量**,方差不可比。

## 三、判定 `closes_as_refuted` 站得住 —— 但理由是【判官独立性】,不是功效

按预注册的判读规则:B 的 CI 跨 0、可分开格 >= 20、两臂方向一致 → `closes_as_refuted`。三条都满足。

而**定性对比是真的**:

| | 判官 | B 中位 | B 均值 | 结论 |
|---|---|---|---|---|
| A15 | IPknot+RNAPKplex(**与面板共用能量模型族**) | +0.0181 | **+0.0392** | 排除 0 |
| P1 合池 | RibonanzaNet(**学习型,无能量模型**) | +0.0000 | **−0.0209** | 跨 0,33 正 / 29 负 |

A15 的 B 在**中位和均值上都是正的**;P1 的中位为零、**均值为负**。这一行卡在 ⏳ 的原因**恰恰就是
那层循环**,所以换成独立判官之后归零,是关掉这一行的**正当理由** —— 只不过这个理由是"判官独立",
**不是我写的"我们拿到了功效"**。

**④ 24/30 → 24/29 = 82.8% 因此仍然成立**,但归因要改写。

## 四、因此,产品建议必须降级

我上一条写的是:"§九 第 9 项说『在拿到功效之前 argmax |confirmed_by| 一行不许动』—— **功效拿到了,
答案是零**"。

**功效没拿到**(单位 64 -> 68)。正确的说法是:**在一个独立判官下 B 归零甚至略负,而 A15 的正值来自
共用能量模型族的判官。** 这足以说明"A15 不能用来支持那条规则",**不足以说明"那条规则可以动了"**。
**这条建议现在不该被执行。** 要执行,先按 per_cell=10 跑一次真正增加格数的版本(合池 170 格)。

## 五、D4S:我那条 caveat 写反了,而实测【加强】了结论

我写的是:"负对照太容易 —— 打乱等于换掉整条 trigger,所以 0.0000 不奇怪"。**查了 15 个案例:**

```
假侧【确实预测出链间配对】:15 个案例合计 24 对(单例最多 7 对)
但命中真配对的:【0 对】
真侧合计 97 对,命中 97 对
```

**所以假侧不是"不配对了",是"配错了位置"。** 这个观察量区分的是**配准(register)**,
不只是"到底有没有配对" —— **负对照比我以为的更有信息,不是更平凡。**

**另一条 caveat 保留**:真值标签来自 RNAcofold,所以证明的是【两个独立族对哪些链间对成形达成一致】,
**不是**哪一边关于真实开关是对的。判定 `calibrator_exists` 站得住。
