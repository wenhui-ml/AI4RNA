## 四、复核在 `m5_review_interval.py` 里查出两个 bug —— 两个都是我的

### bug 1:bootstrap 给每个轮换配错了 g 向量

```python
fn = [f for _n, f in POPS if all(t in G[f] for t in ts[:3])][0]
```
这行挑的是"**第一个**其 g 含有该轮换前三个靶标的人群"。而几乎每个人群都含有几乎所有靶标,
**所以四个轮换全部被拿去和样本2 的 g 做 bootstrap**,而不是各自的评估人群。
点估计是对的(它们直接用轮换数组算),**只有区间用了错的映射**。

**而这件事当时有一个可见的破绽,我没有追**:基准列的 95% 区间报成 **[+0.5754,+0.8556]**,
而点估计是 **+0.5729 —— 落在自己区间的下界之外**。
**一个 bootstrap 区间排除了它自己的点估计,不可能是巧合。**

### bug 2(已在 M5 审计里记过):置换在每轮内部独立打乱 ⇒ 零分布窄了约一倍

### 修正后的数(`m5_review_fix.py`,与 M6 同一套正确实现)

**三件事照写:**
1. **M5 的冻结裁定不变** —— K1 触发,`no_invariant_found_in_measurement_geometry`,而且**修正后的统计量证实了它**:
   十个候选按 Bonferroni 无一通过。
2. **`ed_range` / `ed_sd` 在【未校正的 95% 水平】上排除 0** —— 那是 `unresolved` 的线索,
   **不是发现**;十个候选的多重性必须付。
3. **修正后的置换 p 是 0.023 / 0.034,而 M5 报的是 0.001 / 0.004** ——
   第 55 条的诊断被定量证实:每轮独立打乱把 p 值压小了约一个量级。
