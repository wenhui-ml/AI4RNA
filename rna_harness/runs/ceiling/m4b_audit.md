## 三、这回答了 M4 判不了的那个问题,**答案与 M4 的解释相反**

`m4_audit.md` 第五节的解释是:「n 越大 oracle 越强,而模型选中的那条跟不上」——
这句话只约束**分母**,所以它容许"分子仍在上升、只是比值被稀释"。

**分子没有上升。分子也见顶了,而且崩得比比值更难看:**

> **出厂面板的绝对增益 +0.47 → +1.06 → +1.25(n=10 见顶)→ +0.91 → +0.16,
> 到 n=50 区间 [−0.6062,+0.9926] **含 0**。**
>
> **在 n=50 的候选池上,那套 22 列的出厂判据买不到任何可测的东西。**

所以"比值下降"不是一个测量假象,是两件事叠加:可得增益在涨(+2.84 → +8.76),
**而面板拿到的绝对量在 n=10 之后往回走**。这是本实验唯一一个 M4 无法给出的结论。

## 五、K4 这道闸门的形状我写错了 —— 记录,不改裁定

冻结的 K4 要求「`GC_only` 均值 ≥ `A` 均值 **且两者区间不重叠**」。n=50 上
`A` 上界 +0.9926 与 `GC_only` 下界 +0.7083 **重叠了 0.28**,所以 K4 不触发。

**但比较两条【边际区间】重不重叠,是一个比配对差弱得多、而且是错的检验** ——
两个量在同一批靶标上算出来,它们的差有自己的、窄得多的区间:

> **`GC_only − A` 在 n=50 上是 +1.9519 [+0.5570, +3.2905],排除 0。**

**裁定按冻结判据照写(K4 不触发)。但不许把"K4 不触发"读成"GC_only 没有打赢面板"** ——
配对差说它打赢了。这与 `m4_audit.md` 第五节记的 K3 形状错误是同一类毛病:
**我把闸门写在了一个比手头更弱的统计量上。**

## 八、边界

1. **n=50 只有主人群站得住**(53 靶标)。基准4560 / 样本3 / 第四批分别只有 11 / 13 / 0,
   低于地板 20,已跳过并报出。**曲线尾部是单人群证据,不许当复现引。**
   "面板在 n=50 上买不到东西"这句话的复现状态是 **1/1,不是 4/4**。
2. **本实验测的是增益曲线的形状,不是"n 该开多大"的答案。**(声明里冻死的边界)
   后者 = 增益曲线 ∩ 每条候选的成本,成本模型不在本实验里。
3. 本次的"捕获率"若由 AG/(ORACLE−R) 反算,与 M4 表中的数字不同(如 n=10:18.3% vs 16.6%)。
   **两者是不同的估计量**:M4 是逐格比值再平均(mean-of-ratios),这里是均值之比(ratio-of-means),
   加上退化格口径不同。**不许把本表当成对 M4 那张表的更正。**
4. 与 M4 同一批格、同一个构建器(`m1c.build`),但**没有 GC 相消** —— 与 M3/M3c 的口径不可混引。
5. 没有盲人群,只用骨架可形成子集,仍在 Turner 族内。**只量信息量,不判上线。**
