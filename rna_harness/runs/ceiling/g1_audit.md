## 二、审计发现的致命处:**我把嵌套方向搞错了**

原始分量各自的靶标内 ρ:

```
F_nested     −0.2005
E_skeleton   −0.3945
dG_stack     −0.3890        <- |ρ| = 0.389 > M2 的 0.377
```

**`dG_stack` 单独一项就比完整的 γ\* 略好。** 我的 M0→M1→M2 是靠**逐项加**逼近 γ\*,
所以它只能回答"加上 dG_stack 有没有用",**从来没问过"γ\* 有没有胜过那一项自己"。**
K2 想抓的正是这个,而它抓不到 —— **不是闸门失效,是我把闸门装反了。**

补做的比较(同一次 bootstrap 重抽,配对):

> ### **整个 +0.38 的信号,可以用"交叉茎里有几个 G-C 配对"完整复现。**
>
> 精确配分函数那一套(`F_nested` 的 O(L³)、`E_skeleton` 的精确求值)**相对这个计数没有任何增量**,

而这**不是**"两个变量本来就是同一个"那种平凡情形:

- 靶标内 `Spearman(−dG_stack, GC计数)` 均值 **+0.928**、中位 +0.947、min +0.685,

- 粗细差着一个量级:**GC 计数在靶标内只有中位 8 个取值(80 条设计),γ\* 有 78 个。**
  **一个 8 值的粗计数,和一个 78 值的精细量,预测能力在区间内不可分辨。**

## 三、这条把什么打死了、什么没打死(必须分开)

**打死的:** 分析文档第五节那条"**可被打死的预测**"——"γ\* 低的分子应当在试管里更容易失败"。
它**没有被打死在方向上**(符号对、区间排除 0),**它被打死在【内容】上:γ\* 相对一个平凡计数没有增量。**
按本项目自己的判例(检索热启动相对通用 GC-硬度先验为 NULL;`certify.py` 里的
`not_a_stability_artifact / partial_rho_controlling_pair_strength`),**这就叫 NULL。**

**没打死的:第 2 项。** 因为第 2 项是个**逻辑**断言,不是排序断言:

> `F_nested > E_skeleton + dG_stack` ⇒ 在**任何**正的 γ 下靶标都输给精确算出的嵌套集合 ⇒ 它折不出预期结构。

**一个单侧否决器不需要与一个连续分数相关才成立。** 排序含量与阈值跨越是两件事。
所以第 2 项照跑,**但要带一条 G1 新增的削弱:**

> **构造一已被测出【不携带超出平凡计数的排序信息】,所以第 2 项的价值完全押在能量算术本身正确上,
> 来自 G1 的独立经验支持是【零】。** 这比声明里写的那两种情形(K1 触发 / K1 不触发)都要弱,
> 因为 K1 确实没触发,但没触发的那个相关是空的。

**还要带 `g3_audit.md` 第五节的修正:** γ\* 被系统性高估约 2.4 kcal/mol,
所以第 2 项**必须同时报原始计数与 `γ*_computed < +2.4` 的修正计数**,后者只会更多。
